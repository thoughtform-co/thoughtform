# Rule: Brandmark / sigil choreography

Edits here move a brandmark actor across fixed, projected, or in-canvas renderers. Small measurement mistakes show up as hero flashes, between-section float, practice snaps, or a visible SVG-to-particle size jump.

**Read first**

- [ADR-010: Brandmark choreography](../sentinel/decisions/010-brandmark-choreography.md)
- [ADR-023: Corridor Brandmark Physics Core](../sentinel/decisions/023-corridor-brandmark-physics-core.md)
- `.claude/skills/brandmark-choreography/SKILL.md` (checklist + Playwright recipe)
- Related stack: [ADR-008](../sentinel/decisions/008-landing-v7-background-layers.md) (layers)

**Process:** [sentinel/MAINTENANCE.md](../sentinel/MAINTENANCE.md) - run Cycle A after changing triggers; prefer live rects and `onLeave` settlement over new CSS sticky hacks.

**Home-v2 corridor invariant (REWRITTEN 2026-06-25 hybrid):** the live corridor brandmark is **two painters with an invisible seam**, not one. `ProjectedBrandmarkActor` owns the visible mark at full opacity (instant `display: block`, never an opacity fade) while corridor `progress < BRANDMARK_CORE_HANDOFF_PROGRESS` (`= CORRIDOR_TIMELINE.brandmark.thoughtformHold`, currently `0.14` — pulled earlier than the old `0.30` substrate-wrap anchor to give the morph more runway). The instant `progress` crosses that threshold from below, the SVG cuts to `display: none` in the SAME frame that `BrandmarkPhysicsCoreActor` rasterises the SVG's live screen rect (via `rasterizeBrandmarkToWorldPositions` + `worldPositionsToLocal` + `sim.reseed`/`sim.setHomePositions`) into world positions that reproject to those exact CSS pixels — so the eye sees no swap because the particles ARE the SVG at frame N+1. The two painters share a `brandmarkScreenRectRef` (`components/landing/home-v2/brandmarkScreenRectRef.ts`) — the SVG writes its rect every paint frame; the physics-core actor reads it at the swap frame. From there the vertex shader interpolates each particle from its matched-pixel seed to its paired `aTarget3D` (the GLB volumetric wireframe sampled from `/models/brandmark/brandmark.glb` via `sampleBrandmark3D` — the SAME mesh the #services hologram uses) with per-particle staggered `flowT`, +Z recede peaking mid-flow, and low-amplitude XY drift. By `uDepth = 1` (at substrate wrap peak, `progress = 0.42`) every particle has settled exactly on its wireframe home inside the substrate sphere. Pitfalls: cross-fading SVG and particles together (any non-zero opacity overlap reads as the dissolve the user explicitly rejected); using opacity instead of `display: none` for the SVG cut; using a synthetic dome bulge as the morph endpoint instead of `sampleBrandmark3D.armHomes`; making the particles try to look exactly like the SVG at rest (perceptually impossible at corridor density — five revisions tried, all failed; that's why the SVG owns the rest now); lowering `ignite` to create a swirl. The sim stays assembled (`seedAtHome`, `ignite=1`); the render shader owns the wind-blown flat → wireframe interpolation. ADR-023 Invariants 13–14 are the load-bearing contract.

**Harmonization (2026-06-25 follow-up; color superseded by the unify-on-orange note below):** the SETTLED in-sphere mark reads as a crisp, airy wireframe that matches #services so the corridor→Services transition is continuation, not a swap. A `wireCrisp = smoothstep(0.7, 1.0, uDepth)` factor (vertex→`vWireCrisp`) tightens the dots + stills twinkle + shrinks specks (and historically lerped body/accent toward the #services palette), plus a settled alpha trim. The **color lerp is now a no-op** — the whole corridor brandmark is one gold (see unify note) — but the crisp/still/shrink effects remain load-bearing. Production #services is FRONTAL (`restTilt 0/0` in `ServicesStage.tsx`) to match the head-on in-sphere mark — keep both frontal (the sphere's sword↔vertical-orbit alignment depends on a frontal mark). Pitfalls: ramping `wireCrisp` in before uDepth ~0.7 (flattens the fly-in); re-tilting one of {in-sphere mark, #services wireframe} without the other.

**Never-warp + desaturate + align (2026-06-25 follow-up).** The PRESENTED brandmark shape (flat rest + landed wireframe) must never warp/wobble — only the wind-blown flight may move particles. So: the corridor sim is PINNED (`PINNED_CORRIDOR_FORCES` = flow/turbulence 0, returnStrength full) — the morph is vertex-shader-driven off the pinned home, so pinning doesn't touch the transition; the rasterizer guarantees ≥ count unique candidates (no seed-wrap duplicates → no doubled-dot hot spots); and `vCrisp` (high at flat rest AND landed) tightens + stills + flattens size-variance so the shape reads clean. `PRODUCTION_BLENDING` is `normal` (not additive): additive accumulation over the dense mark clipped to a vivid over-saturated gold, normal blending settles at the true muted unified gold (`#b08b42`, see unify note) and matches the normal-blend #services wireframe. `TARGET_HALF = 0.5` is the group-local half-extent the GLB sample normalizes to; the mark's WORLD size is then `BRANDMARK_SPHERE_FILL` (`sceneGeom.ts`, `0.95`) of the sphere's apparent radius so the wireframe FILLS the sphere — its outer extent reaches the visible edge — while the sword tip stays just inside (`1.0` put the sword on the dotted shell and it read as protruding; `0.85` was an over-correction that read as too small). Pitfalls: re-enabling sim flow/turbulence for the corridor (re-warps); reverting to additive (re-saturates); padding the seed/target buffers with zeros instead of wrapping (origin "photon" cluster); raising `BRANDMARK_SPHERE_FILL` toward 1.0 (sword pokes past the sphere again) or dropping it well below 0.9 (mark reads too small inside the sphere).

**Unification — one object into #services (2026-06-25 follow-up).** The corridor core IS the #services centerpiece; it no longer cross-dissolves into a SECOND brandmark in a separate canvas. Gated by `UNIFIED_SERVICES_ARMILLARY` (`components/landing/home-v2/unifiedServicesInstrument.ts`). The core does NOT fade out at the dive (`handoffFade` is now `docked ? 1 : servicesAmbient ? servicesAmbientLevel : 1` — full through the dock + ambient, fading only as `#continuum` nears). The #services orbit armillary is a CHILD of the core's group via `CorridorArmillary` (renders `HologramOrbits` + `DEFAULT_ORBITS` in the SAME corridor canvas, so orbits depth-interleave with the mark and inherit its billboard/drift/scale); a `pointerLookRef` wrapper tilts mark+orbits toward the cursor when parked. Scan anchors publish to `hologramConnectorStore` only once parked; `ServicesStage` writes `activeServiceId` to that store as the cross-tree bridge and stops mounting its own R3F canvas (`showServicesCanvas = useHologramCanvas && !UNIFIED_SERVICES_ARMILLARY`). The standalone `ServicesHologramScene`/`VolumetricBrandmarkArtifact` remain the lab harness. Color flows from `lib/home-v2/goldPalette.ts` (see unify note below for the live values). Pitfalls: reintroducing a separate #services canvas/crossfade (the dissolve the user rejected); ungating the armillary/anchors from `recT`/dissipate (orbits leak into the corridor proper); breaking the mobile/reduced-motion DOM+SVG fallback (it must stay — the corridor never docks there).

**Unify on one gold → darker orange + contain + de-pixelate (2026-06-25 follow-up; CURRENT color contract).** The corridor brandmark is **one continuous color** end-to-end — 2D rest SVG, matched-pixel flight, landed wireframe, orbits, and #services all read the same gold, with NO mid-journey color lerp (the `wireCrisp` color shift is a no-op; its crisp/still/shrink effects remain). The unified value was briefly a too-yellow "Tensor" (`#c2af4c`) and is now the **darker yellow-orange retrofuturistic glow** at the user's request. Live palette in `lib/home-v2/goldPalette.ts`: `TENSOR_GOLD` = `#b08b42` (body, rgb 176,139,66), `TENSOR_ACCENT` = `#dcc176` (accent), `SPHERE_GOLD` = `0xcaa554` (substrate-sphere gimbal + interior particles, a touch lighter). The `TENSOR_*` names are kept as stable semantic labels (not hue names) to avoid churning ~30 import sites; the retired `HANDOFF_*` constants are gone. The 2D rest SVG fill is set via the new `BrandmarkGlyph` `fill` prop (`ProjectedBrandmarkActor` passes `TENSOR_GOLD`); its drop-shadow glow + the mobile fallbacks (`ServicesBrandmarkField`, `CorridorSeamPixelField` `GOLD_RGB`) carry the hardcoded `176, 139, 66`. The global site brand gold `--gold` (`#caa554`, `app/styles/variables.css`) is unchanged — this is scoped to the corridor brandmark + sphere. **Size/containment:** `BRANDMARK_SPHERE_FILL` (`sceneGeom.ts`) = `0.95` — the wireframe FILLS the sphere (outer extent at the visible edge) while staying contained (`1.0` protruded, `0.85` was too small). **Resolution:** `CORRIDOR_DRAW_TARGET` (`BrandmarkPhysicsCoreActor.tsx`) = `2600` (was `1600`, landed keep ≈ 0.27 → ≈ 0.43) + the landed dot-size shrink `mix(1.0, 0.90, wireCrisp)` (was `0.82`) so the landed wireframe reads dense/crisp, not sparse/pixelated; the airy #services centerpiece is `uCleanFieldKeep`-gated and unaffected. Pitfalls: changing the corridor flat color without the SVG fill (handoff pops — they must stay equal); raising `BRANDMARK_SPHERE_FILL` toward 1.0 (protrusion returns); raising the global particle count past 6000 to densify (jumps the sim texture 64×64→128×128 = 4× compute — use `CORRIDOR_DRAW_TARGET` instead).
