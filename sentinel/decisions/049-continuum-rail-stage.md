# ADR-049: Continuum rail stage (the brandmark returns; the tool ↔ collaborator spectrum reads across its centre)

**Date:** 2026-07-17
**Status:** Accepted (spectrum treatment revised same day — see Update 1)
**Flag:** `CONTINUUM_RAIL_STAGE` (`components/landing/home-v2/unifiedServicesInstrument.ts`; presumes `ABOUT_DECK_STAGE`)
**Builds on:** ADR-047 (about deck-flip stage — the transparent-stage + fail-opaque-shield + ambient-retarget pattern this reuses one station down), ADR-029 (the card-ring armillary + `shell-waist` ring), ADR-023 (the corridor brandmark physics core), ADR-030 (the seam-cut ordering invariant).
**Scope:** `lib/services-ring/` (`continuumStageMath.ts`, `continuumStageProgressRef.ts` new), `components/landing/home-v2/continuum/` (the stage: portal, component, data, CSS), `hooks/useContinuumStageScroll.ts` (single writer), `hooks/useCorridorExitScroll.ts` (ambient kill retarget → `#practice`), `home-v2.css` (compositing: `#continuum` transparent + shield, `#practice` cover), `DepthGatewayScene/BrandmarkPhysicsCoreActor.tsx` (mark lift + recede release), `DepthGatewayScene/CorridorArmillary.tsx` (waist getter + waist rail mount), `services/hologram/HologramOrbits.tsx` (per-ring `masterOpacityGetterFor`), `services/hologram/ContinuumWaistRail.tsx` (thumb + ticks, new), `components/landing/v7/landing.css` (`.continuum__title` restyle), the prototype `#continuum` block (`[data-continuum-root]` shell), `app/(marketing)/page.tsx` (CSS import), `LandingPage.tsx` (portal mount), `tests/lib/continuum-stage-math.test.ts` + `tests/lib/v7-parse.test.ts`.

## Context

`#continuum` ("AI isn't software to command. It's intelligence to navigate.") is the vision beat after `#about`. It shipped as a passive DOM station: a static `.crail` slider whose reticle ping-pongs on an autonomous 7s CSS loop (`crailSlideLarge`) between the Tool and Collaborator stops. The owner's brief: About is _who Vince is_; Continuum is _the vision_ — so the brandmark should be deliberately re-introduced here. As the section arrives the WebGL brandmark should come closer (mid-prominence: clearer than the ~0.30 about-ambient ink, subtler than the #services centerpiece), its near-horizontal "Saturn" waist ring should re-brighten, and the tool ↔ collaborator slider should be visualized **on that waist ring** — a reticle thumb travelling its front arc. The headline restyles to the Services masthead recipe; the three labels (Tool · AI lives here · Collaborator) map left/centre/right under the ring.

## Decision — one clock, three envelopes, one thumb

`#continuum` becomes a pinned TRANSPARENT rail stage over the still-live corridor canvas — the ADR-047 grammar, one station down. A 200svh runway (`.continuum-stage-root`, the `[data-continuum-root]` portal slot) pins a sticky 100svh transparent stage; `useContinuumStageScroll` is the single writer of `data-continuum-mode="stage"`, the CSS-var beat mirrors, `--continuum-bg-in` (the shield), and `continuumStageProgressRef` (the cross-root clock). Progress = `clamp01(−root.top / (root.height − vh))`, clamped 0 above / 1 below the runway so every consumer holds byte-stable off-stage.

Three envelopes (`continuumStageMath.ts`, unit-pinned to exact 0 at progress 0):

1. **APPROACH** `[0, 0.30]` — the receded mark lifts from the ~0.30 about-ambient floor to `CONTINUUM_MARK_INK = 0.60` and eases part-way back toward the parked pose (`CONTINUUM_RECEDE_RELEASE = 0.5` of the #services `EXIT_RECEDE_*` scale + camera-forward push, applied ONLY to the two pose lerps — never the opacity dim / point size / clean-field); the waist ring alone re-brightens (`CONTINUUM_WAIST_LEVEL = 1.3`, > 1 lifts `shell-waist`'s 0.68 line above its rest, capped at 1 in `OrbitRing`); the thumb's opacity gate opens.
2. **COPY** `[0.06, 0.38]` — the masthead + three labels reveal via scrubbed `--continuum-copy-in` with per-child `--ci-off` stagger (the about-stage recipe; never `useRevealMotion` — portal nodes are unobserved and `.is-in` is one-shot).
3. **BG-IN** `[0.92, 1.0]` — the fail-opaque shield restores across the runway tail, completing at the unpin (i.e. as `#practice`'s top reaches the viewport) BEFORE the ambient fade even starts (the ADR-030 lockstep ordering).

The **thumb** rides the waist ring's SAME ellipse parametrization `(cos a · r, sin a · r · ecc, 0)` inside `rotation={shell-waist.tilt}` (`ContinuumWaistRail`, a `CorridorArmillary` child so it banks with the parked instrument). The front arc `a = π·(1 − f)` maps `f = Tool (1/6)` to the left and `f = Collaborator (5/6)` to the right; f ping-pongs over 7s (mirroring `crailSlideLarge`) via a **useFrame delta accumulator** (never a wall clock — a tab-hide must not jump the thumb), advancing only while the approach envelope is open, every opacity gated on it (invisible + inert everywhere else). Three tick spheres mark the labelled stops. Spheres, not flat sprites — the ring is near-horizontal, so flat marks read edge-on.

## Decision — compositing (the ambient retarget, one station down)

Under ADR-047 the corridor ambient died as `#continuum` covered. Now BOTH `#about` and `#continuum` are transparent stages the ambient must SURVIVE, so `useCorridorExitScroll` retargets `nextStation` to `#practice` (`#contact` defensive fallback). Nothing else in the hook changes — the ambient bottom gate and the fade envelope already share `nextStationTopVh`, so they expire together by construction (the twice-bitten ADR-030 §6 seam-cut bug stays guarded). `#continuum` drops its authored opaque background for the fail-opaque shield (`#continuum.station::before`, default 1 = opaque, driven to 0 while pinned + capable, restored across the tail); `#practice` becomes the opaque cover (`z-index: 6` while the band is live). `NEXT_STATION_FADE_START_VH = 0.6 / END = 0.0` keep their values, now keyed to `#practice.top`.

## Fallbacks + failure modes

Flag off ⇒ `nextStation` stays `#continuum`, the hook never engages, the portal stage null-renders, the shield defaults opaque ⇒ byte-visually today's passive station. Mobile / reduced-motion / WebGL-fallback / JS-failure ⇒ `data-continuum-mode` absent ⇒ **fail-static**: the existing DOM `.crail` + its 7s CSS loop + `.is-offscreen` pause own the section. The `.continuum__title` restyle to the canonical `.home-v2-station-header__title` recipe (uppercase, 0.04em, gold-wash shadow, em gold 500 upright) is UNCONDITIONAL — both tiers speak the same voice. Every hook disengage path (media flip → null stage ref, corridor fallback, unmount) clears the attribute + vars + ref (the useAboutStageScroll null-ref lesson); a `visibilitychange` re-sync forces an idempotent write on tab return.

## The journey rail anchor — a resolved non-issue

The v7 DOM brandmark journey (`useBrandmarkJourney`) resolves its "rail" keyframe from `querySelector("#continuum .crail__brand")`. Hiding the static `.crail` on the capable path would leave that a `display:none` 0×0 rect, which `journey.ts keyframeCentreY` maps to null → `computeBrandmarkTransform` returns null. The stage therefore renders an invisible `.crail__brand` anchor as a SIBLING of `.continuum-stage` (NOT inside it — the stage is `display:none` while not engaged, which would itself 0×0 the anchor), so it always carries a valid 56×56 rect and wins `querySelector` (placed first via the pre-`.continuum__head` portal slot). **Verified live: the v7 DOM journey is already DORMANT in the home-v2 build** — its sigil / miss / substrate / orbit keyframe targets were all removed with the corridor-replaced stations (only the rail resolves), so `computeBrandmarkTransform` already returns null every frame and the fixed DOM glyph is inert; the WebGL `BrandmarkPhysicsCoreActor` is the live mark. The anchor is thus harmless and future-proof, and the "hiding the crail kills the #practice orbit brandmark" risk is moot (there is no `.approach__orbit__mark` in this build).

## Invariants

1. Every scrubbed channel is a pure function of the CLAMPED continuum clock, exact 0 at progress 0 (flag-off / pre-continuum byte-identical; the ADR-023 Invariant 11 discipline) and constant 1 through `#practice` arrival — no latch, no release guard.
2. The mark opacity lift is a lerp of the about dim PRODUCT toward `CONTINUUM_MARK_INK`, gated by `continuumT`; at `continuumT = 0` it is the exact about dim product. The retargeted `handoffFade` (`servicesAmbientLevel`) still finishes the kill at `#practice`.
3. The recede RELEASE touches ONLY the two pose lerps (`EXIT_RECEDE_SCALE`, `EXIT_RECEDE_DIST`); `deckStill` is untouched (pointer-look stays damped off through continuum).
4. `HologramOrbits.masterOpacityGetterFor` overrides opacity PER RING; absent ⇒ falls back to `masterOpacityGetter` (labs / flag-off byte-identical). The waist re-brighten is opacity-only (its instanceCount draw-on completed while parked); the meridian + card tracks keep the plain `orbitExitGetter` and stay cleared.
5. The fail-opaque shield restore (`--continuum-bg-in` → 1) completes at the unpin BEFORE the ambient fade starts (ADR-030 ordering), keyed to the same `#practice.top` rect the fade envelope reads.

## Consequences / open items

- **Label ↔ ring registration** is a v1 eyeballed CSS clamp (`width: min(88vw, 64svh·1.6)`); verified centred on this desktop viewport (labels, head, canvas all align on the viewport midline). Iteration point: project the ring's `f = 1/6, 1/2, 5/6` to pixels (the `HologramOrbits` node-anchor pattern) and write `--crail-x-l/m/r` for exact registration across the `getParkedInstrumentScaleMul` viewport band.
- **Rail anchor placement** is runway-absolute (`top: 50svh`) for v1 to avoid an engage-time position jump; pinning it precisely to the mark's viewport centre while pinned (so a revived journey's transit would launch from the mark) is an iteration point — moot while the DOM journey is dormant.
- The **services-orbit lab** was NOT extended with a continuum slider this pass: the lab mounts the standalone `ServicesHologramScene`, not `CorridorArmillary` + the actor, so it can show `ContinuumWaistRail`'s thumb in isolation but not the mark lift / waist re-brighten (those are corridor-specific). The real landing verifies the full beat; a thumb-only lab slider is a documented follow-up.
- Left rail: `#continuum` stays a single `kind: "station"` detent (section top) — no beat-level `scrollFraction` was added, so `MANIFEST_ENTRIES` and the drift-guard tests are unchanged.

## Update 1 — the spectrum reads as a BOLD horizontal axis, not the edge-on waist ring (2026-07-17, same day)

**Why:** the owner reviewed the shipped beat and reported it "still a parallax scroll over" with the spectrum NOT reading on the mark. Two findings: (a) the near-horizontal "Saturn" waist ring is edge-on to the camera, so a reticle thumb riding it (`ContinuumWaistRail`) read as a tiny dot near the mark's equator — not as a legible tool ↔ collaborator spectrum; (b) the pinned stage was falling back to the static `.crail` (fail-static) because the engagement hook could miss the code-split corridor's late mount. The brief: a **bold horizontal axis across the mark's centre** (Tool left ↔ Collaborator right) with a travelling marker, the explanatory copy beneath.

**Decision:**

1. **The spectrum is now a bold DOM axis, painted across the mark's centre in the transparent stage** — not a 3D reticle on the waist ring. `ContinuumStage` gains `.continuum-stage__spectrum`: a `min(760px, 62vw)` gold axis line (brighter at centre, where AI lives) with three registration ticks at `THUMB_TICK_FRACTIONS` (1/6 · 1/2 · 5/6), Tool/Collaborator end caps, and a traveling reticle (`.continuum-stage__marker`) that ping-pongs the front span (`--continuum-axis-lo` 16.667% ↔ `--continuum-axis-hi` 83.333%) on the SAME 7s cadence the DOM crail uses — now a pure CSS `continuumMarkerSlide` keyframe (inert off-stage, so it never runs under reduced-motion, which never mounts the stage). The axis is absolutely anchored at `--continuum-axis-y` (default `47svh`, a single tunable knob) so the line sits on the WebGL mark regardless of copy height; the three readable stops flow directly beneath it. The axis draws in on `--continuum-approach` (with the mark); the stops on `--continuum-copy-in`. The axis is `aria-hidden` decorative chrome — the three stop descriptions remain the AT-exposed content (Invariant, plan 6.2, unchanged).
2. **`ContinuumWaistRail` is RETIRED** (component deleted; its mount + import removed from `CorridorArmillary`). The waist ring's re-brighten (`waistContinuumGetter` / `masterOpacityGetterFor` / `CONTINUUM_WAIST_LEVEL`) is KEPT — it is ambiance on the mark as it comes forward, not the spectrum itself, and stays capped ≤ 1. The mark lift + recede release (`BrandmarkPhysicsCoreActor`) are UNCHANGED. `continuumStageMath.ts` is unchanged (`THUMB_F_MIN/MAX/TICK_FRACTIONS` now document the DOM axis geometry; the `continuumThumb*` angle/fraction helpers are retained + still unit-tested but no longer mounted in 3D).
3. **Engagement hardening:** `useContinuumStageScroll` replaces its two fixed settle passes (600ms + 1800ms) with a bounded self-terminating settle loop (400ms cadence, ≤ 20 tries) that re-checks until `engaged` flips true — so the stage takes over the instant the code-split corridor is ready, even if no scroll frame lands after the corridor mounts. Every other channel (single-writer attribute, CSS vars, cross-root ref, disengage-clears-all) is unchanged.

**Superseded:** the ADR body's "on that waist ring — a reticle thumb travelling its front arc" (Context, Decision §"one thumb", Invariant 4's thumb clause). The waist re-brighten half of Invariant 4 still holds. `services/hologram/ContinuumWaistRail.tsx` is removed from Scope.

## Update 2 — masthead inset fix, exit-slide prelude, and the WebGL band returns (2026-07-18, owner)

Three items from an owner review of the About → Continuum beat.

**A. Masthead inset (the "too centered" fix).** The continuum masthead sat one whole `--hud-content-inset` (~145–192px/side) inboard of the shared editorial band. Root cause: `.continuum-stage__inner` carried `padding-inline: var(--hud-content-inset)` ON TOP of the station's own inset padding and the head's `margin-inline: var(--rail-inset)` — a THREE-layer inset where services/about use two (`station padding + --rail-inset` = `--band-margin`, ADR-045/048). Removed that declaration from `.continuum-stage__inner` (and the visually-inert twin on `.continuum-stage__spectrum`); the title left edge now lands on `--band-margin`, byte-matching services/about at every width. This closes the ADR-048 "never re-widen the inset per-section" violation that the original masthead shipped with (the "restyled to the services recipe" claim held for TYPE but not for the inset).

**B. The lead-in exit is a SLIDE-OUT; the ambient survival + mark re-ink retimed.** The owner reported the About→Continuum handoff as "a black pane sliding over, then another" — the two fail-opaque station shields. ADR-047 Update 8 replaces `#about`'s fade-to-shield tail with a slide-out (copy left, portrait right) over the live corridor bed. The knock-on for this stage: the **mark re-ink + waist re-brighten now PRE-WARM during the About slide** via a new composed clock `continuumFormT(aboutP, continuumP)` (continuumStageMath) = `max(CONTINUUM_FORM_PRELUDE · aboutExitT(aboutP), continuumApproachT(continuumP))`, `CONTINUUM_FORM_PRELUDE = 0.4`. `BrandmarkPhysicsCoreActor`'s `continuumT` and `CorridorArmillary`'s `waistContinuumGetter` both swap `continuumApproachT(continuumP)` → `continuumFormT(...)` — the brandmark returns AS the copy/portrait slide away (one continuous motion), then the continuum approach carries it home. Identity 0 pre-exit (byte-identical), unit-pinned (`continuumFormT(≤0.74, 0) = 0`, `(1, 0) = 0.4` plateau across the inter-runway gap, `(·, 1) = 1`). The `#continuum` shield/`--continuum-bg-in` tail is UNCHANGED and is now the load-bearing lockstep cover before the `#practice` ambient kill.

**C. The spectrum returns to the waist ring as a WebGL BAND (lab-first).** Update 1 bailed the spectrum to a DOM axis because the edge-on waist ring made a reticle thumb read as a dot. The insight this pass: the edge-on plane is not the enemy — a band with real 3D THICKNESS reads edge-on as a bold horizontal BEAM crossing the mark's centre. New `ContinuumBand` (`services/hologram/ContinuumBand.tsx`) + pure math (`lib/services-ring/continuumBandMath.ts`, unit-tested): two companion ellipses + a governed particle annulus (the beam body) + graduation ticks crossing the beam + Tool/Collaborator pole diamonds + a camera-facing traveler reticle with a plane-local plumb pin, all placed with `bandRingPoint` (reuses `continuumThumbAngle` so nothing drifts off the drawn ring) and gated by a `formT` clock (inert off-stage). Look-dev lab at `/test/continuum-band` (layer toggles MARK/ORBITS/BAND/CARDS + a lab waist selector that finally previews the re-brighten — closes open item 3). **This pass is LAB-ONLY** (owner: build + review the band before it replaces the live DOM axis). Live wiring is a documented follow-up: mount in `CorridorArmillary` behind `CONTINUUM_RAIL_STAGE && ringCapable` with `formTGetter = continuumFormT(...)`; project the waist `f = 1/6, 1/2, 5/6` to screen px (`continuumAnchors` on `hologramConnectorStore`) to dock the DOM stop labels (closes open item 1, `--crail-x-l/m/r`); delete the `.continuum-stage__axis` DOM/CSS. Until then the Update 1 DOM axis stays live.
